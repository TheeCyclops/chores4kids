# Chores4Kids roadmap

1. Keep the standalone fork and bundled card stable; preserve existing runtime data and MagicMirror compatibility.
2. Close relevant [verification gaps](known-bugs.md) during explicitly authorized acceptance tasks; establish backup/restore readiness before Lenovo upgrade or storage migrations.
3. Design shared reward points with the user before service/storage/UI implementation. Coordinate separate repository commits and compatible releases.
4. Publish/install only through a requested release/deployment task using [RELEASING.md](../RELEASING.md).

Source checkpoints normally commit and push to `main`; they are not releases or live installations. See [progress](progress.md).
